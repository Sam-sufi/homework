# 分层重构后的六项质量复核

评审基线为 `a983b1e`。本轮在队友的分层实现上修改，并使用同一份 HTTP 集成测试对照运行。原始基线通过 12 项，新增专项中 5 项断言失败，另 1 项因商品详情缺少收藏状态字段报错。修正后 18 项全部通过。

| 昨日问题 | 重构基线的表现 | 本轮修正与验证 |
| --- | --- | --- |
| Q01 注册姓名 | 提交 JSON null 时返回 200，文本工具会把空值转换成字符串。 | `core.py / text` 先检查类型，再去除首尾空格并检查长度。空值、数组、数字均返回 400，测试学号未写入数据库。 |
| Q02 发布金额 | 提交字符串 Infinity 后取整溢出，返回 500。 | `services.py / _product_fields` 将溢出归入金额输入错误。复测返回 400，商品未入库。编辑与发布共用该函数。 |
| Q03 审核决定 | 管理员提交字符串 “false” 时接口返回 200，非空字符串进入同意分支。 | `core.py / boolean` 严格读取 JSON 布尔值。商品审核、撤回审批和争议裁定共用该检查。商品审核专项复测返回 400，商品保持待审核。 |
| Q04 收藏重试 | `favorite` 依据当前记录切换状态。旧详情接口没有 favorite 字段，专项在读取该字段时报错。 | `services.py / favorite` 按目标状态写入，详情接口返回本人的收藏状态，按钮据此发送收藏或取消指令。连续收藏两次后列表中一条，连续取消两次后零条；每次读取详情均与列表一致。 |
| Q05 通知故障 | 强制站内通知插入失败后，正常下单返回 409。 | `db.py / notify` 随主交易保存待投递记录；`api.py / api_mine` 打开收件箱时投递。故障期间一笔订单已生成、商品已预订、待办保留。解除故障后连续打开两次收件箱，只收到一条通知。 |
| Q06 争议中驳回撤回申请 | 买家确认并申请撤回，卖家发起争议后，管理员驳回申请收到 400“订单状态已改变”。 | `services.py / handle_withdrawal` 只在批准时检查订单是否可撤回。驳回复测成功，申请为已驳回，订单仍处于争议处理中，买家确认时间保持原值。 |

在仓库的 `完整项目` 目录执行 `python -m unittest discover -s tests -v` 可复核接口及数据库断言。前端脚本已通过 `node --check static/app.js`。上述计数对应本次重构分支；收藏按钮的浏览器点击流程未单独实测。
