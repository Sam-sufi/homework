## 0 本文的来历与边界

本文不是"设计先行"的产物，而是在系统实现完成后，依据代码与需求**倒推整理**出的架构基线，用途是：

1. 让架构决定**可被复核**（谁定的、为什么、代价是什么）；
2. 给接口、阶段计划、测试证据提供**唯一引用点**；
3. 把"代码里有但文档没写"的机制固化下来，避免后续改动踩空。

因此本文有两个诚实性约束：**只描述代码里真实存在的机制**；**与需求不一致处一律按"演示版裁剪"登记**（见 `00_基线索引.md` §4.2），不美化，也不冒充实现在先。

## 1 目标与约束

### 1.1 业务目标

十项必需功能（FR-01～FR-10）加四项闭环需求（FR-11～FR-14）在单校园、单件库存、线下交付、线下结算的前提下可用；正常交易闭环无缺口；并发下单最多一单成功；越权请求被拒绝。

### 1.2 硬约束（决定架构形状的几条）

| 约束 | 来源 | 对架构的影响 |
| --- | --- | --- |
| 无第三方 pip 依赖，Python 3.10+ 直跑 | E-01、环境清单 | 不用 Flask/Django/ORM；路由、会话、静态文件自实现 |
| 单机本地部署，默认 127.0.0.1:8000 | 环境清单 | 单进程 `ThreadingHTTPServer`；SQLite 文件库 |
| 数据可备份、可迁移、不级联删历史 | BR-10、NFR-05 | 逻辑归档（`review_deleted`、`frozen`）；`migrate_db` 幂等升级 |
| 前端零构建、零外网资源 | 环境清单 | 原生 HTML/CSS/JS，CSP `default-src 'self'` |
| 每次写操作校验凭证、角色、归属、当前状态 | FR-01～FR-14 共性要求 | 写操作全部收敛到单一入口 `act()` |

### 1.3 范围边界

**业务范围外**（需求本身就不含）：在线支付与资金托管、物流配送、跨校交易、借用归还（BR-12）。

**演示版裁剪**（组内决定 2026-11-12，明细见 `00_基线索引.md` §4.2）：认证只保留学号+密码（无手机号/短信/统一身份对接）；评价只由买家发起、修改以追加文字体现；管理员单一角色、无申诉流程；争议只有文字说明、无附件与 48h 时限；商品列表无分页、导出仅 CSV；通知不分类型、无重试。

**口径**：需求规格说明书 v3.1 保持完整需求不变；本基线描述的是**演示版实际交付的范围**，两者差异以裁剪登记为准，不反过来修改需求。

## 2 架构总览

### 2.1 逻辑结构

```text
┌──────────────────────────────────────────────────────────┐
│ 浏览器（static/index.html + app.js + style.css）          │
│  原生 Fetch 调用 /api/*，Cookie: sid，请求头 X-CSRF-Token │
└───────────────────────────┬──────────────────────────────┘
                            │ HTTP/1.1 + JSON
┌───────────────────────────▼──────────────────────────────┐
│ ThreadingHTTPServer（每请求一线程）                       │
│  Handler.do_GET          查询与静态资源                   │
│  Handler.do_POST         写操作，统一 BEGIN IMMEDIATE     │
│   ├─ 静态白名单：/ /app.js /style.css /favicon.ico        │
│   ├─ Handler.user()      会话解析（sessions 表）          │
│   └─ act(db,user,act,d)  业务规则/权限/状态转换单入口     │
└───────────────────────────┬──────────────────────────────┘
                            │ sqlite3（timeout=15s，外键开启）
┌───────────────────────────▼──────────────────────────────┐
│ data/campus.db  16 张表 + 9 个索引/唯一约束               │
│ 业务表：users products orders favorites messages reviews  │
│         review_tags review_images review_replies          │
│         review_deleted reports withdrawals notices         │
│         confirmation_history audit sessions               │
└──────────────────────────────────────────────────────────┘
```

### 2.2 技术基线

| 关注点 | 选择 | 决策编号 |
| --- | --- | --- |
| HTTP 服务 | `http.server.ThreadingHTTPServer` + 自写路由分发 | ADR-001 |
| 数据存储 | SQLite 单文件 `data/campus.db`，无 ORM | ADR-002 |
| 并发控制 | 写事务 `BEGIN IMMEDIATE` + 部分唯一索引 | ADR-003 |
| 密码 | PBKDF2-HMAC-SHA256，16 字节随机盐，160000 迭代 | ADR-004 |
| 会话 | `sessions` 表 + HttpOnly/SameSite=Strict Cookie，24h | ADR-005 |
| CSRF | 会话内 `csrf` 随机串 + 请求头双提交比对 | ADR-005 |
| 代码组织 | 单文件分层（工具函数 → 业务 `act()` → HTTP `Handler`） | ADR-006 |
| 冻结语义 | `products.frozen` 标记，而非新增状态 | ADR-007 |
| 评分存储 | 整数十分位（10–50），避免浮点比较 | ADR-008 |
| 图片 | 商品图 base64 存 TEXT；评价图 BLOB + 鉴权读取端点 | ADR-009 |
| 通知 | `notices` 表，与业务写入同事务 | ADR-010 |
| 审计 | `audit` 表，每个成功写操作一条 | ADR-011 |
| 升级 | `migrate_db()` 幂等列/表迁移 | ADR-012 |

## 3 分层与模块职责

分层靠**函数约定**而不是包结构（单文件，见 ADR-006）。

| 层 | 组成 | 职责 | 允许依赖 |
| --- | --- | --- | --- |
| 接入层 | `Handler.do_GET/do_POST`、`Handler.send` | 解析 URL/JSON/Cookie、限流校验、状态码映射、安全响应头 | 会话层、业务层 |
| 会话与安全层 | `Handler.user`、`password_hash`、`valid_password`、CSRF 比对、`Origin` 校验 | 身份识别、密码散列、跨站防护 | 数据访问层 |
| 业务层 | `act(db,user,action,d)` | **唯一**的业务写入口：参数校验、权限、状态转换、通知、审计 | 数据访问层、查询函数 |
| 查询函数 | `product_reviews`、`order_review`、`seller_page`、`stats`、`review_payloads`、`review_tag_counts` | 只读聚合与展示形状 | 数据访问层 |
| 数据访问层 | `connect`、`rows`、`Database`（连接上下文管理器） | 连接生命周期、行转 dict、外键开启 | sqlite3 |
| 初始化/运维 | `init_db`、`migrate_db`、`backup.py`、`run.py` | 建库、种子数据、备份、启动参数 | 数据访问层 |
| 前端 | `static/index.html`、`app.js`、`style.css` | 视图与交互；**不做任何权限判断的替代** | HTTP API |

> 关键约定：**任何绕过 `act()` 直接写表的代码都视为架构违规**。`register`/`login`/`logout` 是仅有的三个例外（`act()` 之前必须先有身份），它们各自显式 `commit()`。

## 4 运行动视图：一次写请求

以"买家下单"为例：

1. `do_POST` 校验 `Content-Type: application/json`、`Origin` 与 `Host` 同源、`Content-Length` 在 (0, 32MB]；
2. `BEGIN IMMEDIATE` 抢占写锁（避免读后写竞争）；
3. `Handler.user(db)` 用 `sid` Cookie 查 `sessions`（`expires > now`）拿到 `users.*, csrf`；
4. `hmac.compare_digest(X-CSRF-Token, sessions.csrf)`，失败即 400；
5. `act()` 内：`need()` 逐项校验（非本人商品、商品在售未冻结、卖家未封禁）→ 插入 `orders`（`status='待接单'`）→ 更新 `products.status='已预订'` → `notify()` 写 `notices`；
6. 追加一条 `audit`；
7. `commit()`；响应 `{'ok':True,...}`；
8. 任一步抛出 `BusinessError` → 400；`sqlite3.IntegrityError` → 409；其他异常 → 500 并打印堆栈到服务端控制台（不回传内部信息）。

**并发保护是双层的**：`BEGIN IMMEDIATE` 让写操作串行化；`one_active_order` 部分唯一索引在数据库层拒绝第二条有效订单（ADR-003）。测试 `test_concurrent_order_only_one_wins` 用多线程真实 HTTP 验证。

## 5 数据架构

### 5.1 实体与关系（对应 DM-01）

| 表 | 主键/唯一 | 关键约束与含义 |
| --- | --- | --- |
| `users` | `id`；`student` UNIQUE | `role` 取 `admin`/`student`；`banned_until` 为解封时间戳（0 表示未封禁） |
| `sessions` | `token` | `csrf`、`expires`；登录时清理过期会话；24 小时有效 |
| `products` | `id` | `price>0`（单位：分）；`status` 8 态；`frozen` 违规标记；`reason` 审核/冻结意见 |
| `orders` | `id` | 快照字段 `title`/`price`；双方确认时间 `buyer_confirm`/`seller_confirm`；`completed` 完成时间 |
| `favorites` | (`user_id`,`product`) | 复合主键保证收藏唯一 |
| `messages` | `id` | 咨询消息；仅业务双方可读 |
| `reviews` | `id`；UNIQUE(`order_id`,`author`) | `rating` 整数 10–50（十分位）；`hidden*` 为隐藏/删除留痕字段 |
| `review_tags` | (`review_id`,`tag`) | 标签去重；按标签筛选 |
| `review_images` | `id` | `mime` + `bytes` BLOB；`position` 控制顺序 |
| `review_replies` | `review_id` UNIQUE | 卖家回复，一条评价一条回复 |
| `review_deleted` | `order_id` | 硬删除后的墓碑，禁止再次评价 |
| `reports` | `id`；UNIQUE(`author`,`product`) | 同一人对同一商品只能举报一次 |
| `withdrawals` | `id` | 撤回确认申请；`status` 待审核/已批准/已驳回 |
| `notices` | `id` | `seen` 已读标记；无类型字段（DEV-12） |
| `audit` | `id` | `actor/action/target/detail(JSON)/created` |
| `confirmation_history` | `id` | 撤回获批时留存的确认撤销记录 |

### 5.2 完整性约束（数据库层，不依赖应用层自觉）

- 部分唯一索引 `one_active_order ON orders(product) WHERE status IN ('待接单','待交付','争议处理中')` —— **单件商品只能有一条有效占用**；
- 部分唯一索引 `one_pending_withdrawal ON withdrawals(order_id) WHERE status='待审核'` —— 同一订单同时只有一条待审撤回；
- `reviews.rating BETWEEN 10 AND 50`、`products.price > 0` 的 `CHECK`；
- `PRAGMA foreign_keys=ON`（每次连接都设置）；
- 删除评价用"墓碑表 + 物理删除"，不级联删订单（BR-10）。

### 5.3 单位与格式约定

| 项 | 约定 | 位置 |
| --- | --- | --- |
| 金额 | 数据库存**分**，接口出入参用**元**（两位小数），`round(float(v)*100)` 转换 | `act()`、`stats()` |
| 时间 | Unix 秒（整数）；前端按本地时区渲染 | `now()` |
| 评分 | 整数十分位；接口返回 `rating/10` 的浮点 | `review_payloads()` |
| 图片 | 商品图 base64 data URL（≤5MB，仅 PNG/JPEG）；评价图 BLOB | `publish`、`review` |

> 金额用分、评分用十分位，都是为了避开浮点相等比较——这是 ADR-008 的直接后果。

## 6 关键技术机制

### 6.1 会话与请求防护

| 机制 | 实现 | 失效方式 |
| --- | --- | --- |
| 会话票据 | 32 字节 `secrets.token_urlsafe`，存 `sessions`，24h 过期 | 过期后 `user()` 返回 `None` → 400 "请先登录" |
| Cookie 属性 | `HttpOnly; SameSite=Strict; Path=/; Max-Age=86400` | 前端 JS 读不到 `sid` |
| CSRF | 登录响应返回 `csrf`，前端存内存并回填 `X-CSRF-Token`；服务端 `compare_digest` | 不匹配 → 400，需刷新页面重新取 `/api/me` |
| 跨站来源 | `Origin` 存在时必须与 `Host` 同源 | 不一致 → 400 |
| 登录爆破 | 同一 `IP:学号` 连续失败 5 次锁定 5 分钟（**进程内字典**） | 服务重启清零（DEV-01） |
| 响应头 | `nosniff`、`no-store`、CSP（`default-src 'self'`、`img-src 'self' data:`） | 由 `Handler.send` 统一添加 |

### 6.2 事务边界

- 写请求：`connect()` 后立刻 `BEGIN IMMEDIATE`，`act()` 全部 DML 与 `notify()`、`audit` 在同一事务内，末尾 `commit()`；
- 只读请求：不开显式事务，连接上下文退出即结束；
- `Database.__exit__` 关闭连接，异常时由 sqlite3 回滚（`test_transaction_rollback_on_invalid_and_own_order` 验证非法请求不留半成品）。

### 6.3 幂等语义（现状，含差异）

| 请求 | 重复调用行为 | 与需求是否一致 |
| --- | --- | --- |
| 下单 | 同一买家对同一商品存在有效订单时返回 `ok:True + order_id`，不新建 | 一致 |
| 接单 | 已处于"待交付"时返回 `ok:True, "订单已经接单"` | 一致 |
| 取消 | 已"已关闭"时返回 `ok:True, "订单已经关闭"` | 一致 |
| 交付确认 | 已有本人确认时间则不再覆盖 | 一致 |
| 收藏 | **切换语义**：再次调用取消收藏 | 与"重复收藏不重复写入"表述不同，属设计选择，需在评审确认 |
| 评价 | 重复提交返回 400"该订单已评价" | 与需求 3.1 的"幂等"表述不同，按演示版口径接受（Q-03） |

### 6.4 状态机落位

完整 19 条转换（ST-01～ST-19、ST-K01～K03）见需求附件 `E-05_状态转换说明表.md`。落位方式：

| 状态机 | 落位 | 说明 |
| --- | --- | --- |
| 商品 SM-01 | `products.status` 8 值 + `products.frozen` | `status` 取值：草稿**未使用**、待审核、已驳回、在售、已预订、已售出、已下架；违规冻结用 `frozen=1` 叠加（ADR-007） |
| 订单 SM-02 | `orders.status` 5 值 | 待接单、待交付、已关闭、争议处理中、已完成 |
| 占用不变量 | `one_active_order` | 商品"已预订" ⇔ 存在有效订单；ST-05/ST-07/ST-08 与订单转换同事务 |

非法转换统一由 `need()` 抛 `BusinessError`，返回 400 并带中文原因；**没有任何路径允许把终态（已完成/已关闭）改回中间态**。

### 6.5 权限校验的位置

权限判断只出现在两处，且都在服务端：

1. `act()` 开头的封禁检查与动作白名单（`new_actions` 拒绝封禁期新增业务）；
2. 各动作分支内的 `own_order()`、`administrator()`、`uid==product['seller']` 等断言。

前端隐藏按钮**不构成**权限控制；`GET /api/product` 对不可见商品返回 400，`GET /api/orders` 只返回本人参与的订单。测试 `test_freeze_and_ban_keep_existing_fulfillment` 覆盖"封禁后仍可确认交付"。

### 6.6 错误语义

| 场景 | HTTP | 响应体 |
| --- | --- | --- |
| 业务校验失败、未登录、参数类型错、接口不存在 | 400 | `{"error":"中文原因"}` |
| 唯一约束冲突（重复举报、并发下单输家、学号已存在） | 409 | `{"error":"该操作已存在、已被占用或账号重复，请刷新后重试"}` |
| 服务端未预期异常 | 500 | `{"error":"服务器处理失败"}`（详情只打服务端日志） |

前端按 `error` 字段直接提示，不依赖状态码做分支——这是现状，若后续接入其他客户端建议改为按状态码分支。

### 6.7 图片与文件

- 商品图：`publish/edit` 接收 `data:image/(png|jpeg);base64,...`，校验魔数与 5MB 上限后以字符串存 `products.image`；
- 评价图：最多 3 张（`MAX_REVIEW_IMAGES=3`），存 `review_images.bytes` BLOB，通过 `GET /api/review_image?id=` 鉴权后返回（仅评价未隐藏且订单已完成，或管理员）；
- 无视频、无文件上传（DEV-04/DEV-06）。

### 6.8 通知与审计

- `notify(db,uid,body)` 在**业务事务内**写 `notices`，因此"业务成功但通知失败"在本地单库里不会发生（代价：通知写入失败会连带回滚业务，与 FR-14"通知失败不撤销业务事务"的要求相反，登记为设计偏差，见 `03_接口与关键设计说明书.md` §6）；
- `act()` 末尾统一写 `audit`，`detail` 为除 `password`/`image`/`images` 外的入参 JSON（截断 2000 字符）——满足"日志不含明文密码"，但没有"前后状态"字段（NFR-05 部分满足）；
- `read_notices` 一次性把本人全部未读置已读，无单条已读（DEV-12）。

### 6.9 迁移策略

`migrate_db()` 在建表前执行：检测 `reviews` 是否存在 `hidden` 列，缺失则 `ALTER TABLE ADD COLUMN`；更老的"无 `created` 列"版本走"改名 → 新建 → 搬数据（评分 ×10）→ 删旧表"。整个流程幂等，`test_legacy_database_migration` 覆盖。

## 7 接口风格

- 统一前缀 `/api/`；查询用 `GET + query string`，写操作用 `POST /api/<动作名>` + JSON；
- 写操作没有 RESTful 资源路径，而是"动作名"（`order`/`accept`/`confirm`/`resolve`），便于把权限与状态断言集中在 `act()` 的同一处；
- 返回：成功 `{"ok":true,...}`，失败 `{"error":...}`；列表统一包在具名字段里（`products`/`orders`/`messages`）；
- 导出：`GET /api/export` 返回带 BOM 的 CSV，已完成订单，做了公式注入防护（以 `=+-@` 开头的标题前置单引号）。

接口级契约（字段、权限、错误、示例）见 `03_接口与关键设计说明书.md`。

## 8 部署与运维

| 项 | 现状 |
| --- | --- |
| 启动 | `python run.py [--port 8000]` 或双击 `启动系统.bat`；`create_server` 内先 `init_db` 再 `serve_forever` |

| 备份 | `python backup.py`，使用 `sqlite3.Connection.backup()` 在线备份到 `data/backups/campus_<时间戳>.db`，无需停服 |
| 恢复 | 停服 → 用备份文件替换 `data/campus.db` → 启动；**尚无恢复演练记录**（NFR-05 缺口） |
| 端口占用 | `run.py` 捕获 `OSError` 并提示换端口 |
| 日志 | 只有 500 时的 `print`；业务日志在 `audit` 表。无文件日志轮转 |
