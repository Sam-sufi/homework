## 2 ADR 记录（模板B）

### ADR-001 用标准库 HTTP 服务替代 Web 框架

- **状态**：已接受（组内确认 2026-11-12）　**确认人**：项目组（组长 夏天）　**复核人**：李哲剑　**日期**：2026-11-12
- **背景**：课程要求解压即可运行、无第三方依赖（环境清单 1.2）；功能为单机本地 Web。
- **比较**：A. Flask——路由/模板省事，但需 pip 安装，可能因网络失败；B. `ThreadingHTTPServer` + 自写分发——零依赖，但会话、静态文件、错误映射都要自己写；C. FastAPI——额外需要 ASGI 服务器。
- **决定**：采用 B；不采用 A、C。
- **理由**：零依赖是硬约束；业务接口数量可控（11 个查询 + 31 个动作），自写成本可接受。
- **代价**：无中间件生态、无自动参数解析；`Handler` 内 `try/except` 承担了框架的错误映射职责。
- **验证**：`python -m compileall` 通过；19 项真实 HTTP 集成测试（`tests/test_app.py`）覆盖主链路。
- **重新评估条件**：需要 WebSocket、模板渲染、文件上传分片，或课程允许联网安装依赖。
- **替代关系**：无。

### ADR-002 数据存储用 SQLite 单文件，不引入 ORM

- **状态**：已接受（组内确认 2026-11-12）　**确认人**：项目组（组长 夏天）　**复核人**：李哲剑　**日期**：2026-11-12
- **背景**：单机、单校园、演示规模；需要可备份、可整体拷贝提交（环境清单要求保留 `data` 目录）。
- **比较**：A. SQLite 文件库——零部署、事务完整、备份简单；B. MySQL/PostgreSQL——需安装与配置，评分环境不可控；C. 文件/内存结构——无法保证并发与崩溃一致性。
- **决定**：A。
- **理由**：交付形态要求"解压即跑"；写并发量小（单校学生演练）。
- **代价**：写操作全局串行（见 ADR-003）；无连接池；跨进程备份需用在线备份 API。
- **验证**：`test_concurrent_order_only_one_wins` 证明并发下单只有一单成功；`backup.py` 已验证可生成备份文件。
- **重新评估条件**：多实例部署、或写事务排队导致接口超时（>3s，NFR-01）。
- **替代关系**：无。

### ADR-003 写操作用 `BEGIN IMMEDIATE` + 部分唯一索引保证"单件商品只有一条有效订单"

- **状态**：已接受（组内确认 2026-11-12）　**确认人**：项目组（组长 夏天）　**复核人**：李哲剑　**日期**：2026-11-12
- **背景**：FR-05/BR-04 要求先到先得、并发下单最多一单成功、不得出现两个占用。
- **比较**：A. 应用层 `threading.Lock`——单进程有效，重启/多进程失效，且锁粒度粗；B. `BEGIN IMMEDIATE` + `one_active_order` 部分唯一索引——数据库层双重保护；C. 乐观锁版本号——需要额外字段与应用层重试逻辑。
- **决定**：B，`act()` 中先校验再写，异常由 `IntegrityError → 409` 兜底。
- **理由**：索引是数据库强制的不变量，不依赖任何一段应用代码"记得检查"。
- **代价**：写请求串行；热点商品下单会短暂排队；需保证事务内不夹杂耗时操作（如 base64 解码图片在事务外更佳，现状在事务内）。
- **验证**：`test_concurrent_order_only_one_wins`（多线程真实 HTTP）；`test_transaction_rollback_on_invalid_and_own_order`（非法请求不留半成品）。
- **重新评估条件**：启用 WAL 后读并发提升、或写超时出现；或迁移到支持行锁的数据库。
- **替代关系**：无。

### ADR-004 密码用 PBKDF2-HMAC-SHA256 加盐散列

- **状态**：已接受（组内确认 2026-11-12）　**确认人**：项目组（组长 夏天）　**复核人**：李哲剑　**日期**：2026-11-12
- **背景**：NFR-02/NFR-06 要求安全存储密码、日志不得含明文。
- **比较**：A. 明文/MD5——不可接受；B. `hashlib.pbkdf2_hmac('sha256', …, 160000)` + 16 字节随机盐；C. `scrypt`——标准库可用但参数选择更易错。
- **决定**：B；存储格式 `salt:hash`，校验用 `hmac.compare_digest`。
- **理由**：标准库内置、参数明确、实现 6 行；比较用常量时间。
- **代价**：单次登录约数十毫秒 CPU；迭代次数写死在代码里，未来需要版本前缀才能升级。
- **验证**：`test_registration_authentication_and_csrf` 覆盖注册/登录/错误密码；人工检查审计记录不含密码字段。
- **重新评估条件**：需要支持密码升级（迭代次数提升）时，改为带算法标识的存储格式。
- **替代关系**：无。

### ADR-005 会话用服务端 `sessions` 表 + HttpOnly Cookie，CSRF 用头部双提交

- **状态**：已接受（组内确认 2026-11-12）　**确认人**：项目组（组长 夏天）　**复核人**：李哲剑　**日期**：2026-11-12
- **背景**：需要登录态、防 CSRF，且不引入 JWT 库（无第三方依赖）。
- **比较**：A. 自签 JWT——需实现签名与撤销，标准库可做但复杂；B. 服务端会话表 + 随机 token；C. 仅 Cookie 不校验 CSRF——存在跨站写风险。
- **决定**：B + `X-CSRF-Token` 与 `sessions.csrf` 常量时间比对；Cookie 加 `HttpOnly; SameSite=Strict`。
- **理由**：可随时 `DELETE FROM sessions` 撤销；CSRF token 与会话绑定，前端从 `/api/me` 取。
- **代价**：每次请求多一次会话查询；`SameSite=Strict` 下从外部链接进入需重新取 token。
- **验证**：`test_registration_authentication_and_csrf` 中缺失/错误 CSRF 返回 400。
- **重新评估条件**：引入跨域前端，需要改为 `SameSite=Lax` + 更细粒度 CORS。
- **替代关系**：无。

### ADR-006 单文件分层，不拆包

- **状态**：已接受（组内确认 2026-11-12）　**确认人**：项目组（组长 夏天）　**复核人**：李哲剑　**日期**：2026-11-12
- **背景**：课程提交物是"完整项目"目录；三人协作但有 Git 分支管理；无打包/部署流程。
- **比较**：A. 单文件 `app.py`，靠函数段分层；B. `models/ services/ views/` 拆包；C. 单文件但按类拆分（`Repository`/`Service`）。
- **决定**：A。
- **理由**：交付与评阅成本最低；跨文件跳转在 300 行内不构成负担；改错风险集中在 `act()`。
- **代价**：`act()` 已约 130 行，SQL 与业务判断混排；多人同时改冲突面大；无类型约束。
- **验证**：`compileall` + 19 项测试通过；代码审阅时以 `act()` 为唯一入口检查权限。
- **重新评估条件**：单文件超过 600 行，或需要第二个人并行改业务分支——届时执行 B。
- **替代关系**：无。

### ADR-007 冻结用 `products.frozen` 标记，不新增第 9 个商品状态

- **状态**：已接受（组内确认 2026-11-12）　**确认人**：项目组（组长 夏天）　**复核人**：李哲剑　**日期**：2026-11-12
- **背景**：FR-09 定义 8 个状态且要求"已售出商品违规仅隐藏、不改变已售出状态"。
- **比较**：A. 新增"违规冻结"状态——状态机变 9 态，已售出商品无法既保持"已售出"又"被冻结"；B. 独立 `frozen` 标记叠加在状态之上——保留原有状态，查询时 `frozen=0` 过滤；C. 软删除——丢失违规留痕。
- **决定**：B；`freeze` 写 `frozen=1, reason=...`，`unfreeze` 写回 0。
- **理由**：一个字段同时满足"在售转冻结后不可交易""已售出仅隐藏"两种需求，且不破坏状态机。
- **代价**：所有对外查询都必须记得加 `frozen=0`（漏一处即泄漏违规内容）；"违规冻结"不是一个可枚举状态，统计与报表口径需另行说明。
- **验证**：`test_freeze_and_ban_keep_existing_fulfillment` 覆盖冻结后不可见、已售出商品冻结仅隐藏。
- **重新评估条件**：出现"冻结需区分原因/期限/申诉"的强需求时，改为独立 `moderation` 对象（子表）。
- **替代关系**：无。

### ADR-008 金额存"分"、评分存"十分位"

- **状态**：已接受（组内确认 2026-11-12）　**确认人**：项目组（组长 夏天）　**复核人**：李哲剑　**日期**：2026-11-12
- **背景**：价格筛选、成交额统计需要精确相等与求和；评分允许 4.6 这类一位小数（需求 1–5 分）。
- **比较**：A. 用 `REAL` 存元/分——浮点比较与累加出现 3499.9999；B. `INTEGER` 存分、评分存 `rating*10`；C. `TEXT` 存定点小数——比较需 CAST。
- **决定**：B。接口层出入参仍是"元"，转换集中在 `act()` 与 `stats()`。
- **理由**：整数比较精确、`SUM` 无误差、索引友好。
- **代价**：每个接口都要记得乘/除 100；前端展示要 `(price/100).toFixed(2)`；`CHECK(rating BETWEEN 10 AND 50)` 是最后一道防线。
- **验证**：`test_review_once_rating_and_averages` 断言平均分四舍五入到 1 位；`stats()` 的成交额测试。
- **重新评估条件**：引入多币种或含税费计算时，改用 `Decimal` + 字符串存储。
- **替代关系**：无。

### ADR-009 评价图存 BLOB 并走鉴权端点；商品图存 base64 文本

- **状态**：已接受（组内确认 2026-11-12）　**确认人**：项目组（组长 夏天）　**复核人**：李哲剑　**日期**：2026-11-12
- **背景**：环境约束不允许引入对象存储；评价图需按可见性控制访问（隐藏评价的图不能公开）。
- **比较**：A. 落磁盘目录 + 静态直链——实现简单，但无法按评价可见性鉴权；B. BLOB 入库 + `GET /api/review_image?id=` 鉴权；C. 全部 base64 塞进评价 JSON——响应体膨胀。
- **决定**：评价图 B，商品图沿用 C（单张、只随详情返回）。
- **理由**：BLOB 让"隐藏评价 → 图片一并不可见"成为一条 SQL 判断；商品图单张、体积可控。
- **代价**：数据库文件随图片增长（备份体积变大）；读图多一次查询；无缩略图与缓存头。
- **验证**：`test_review_tags_images_and_tag_filter`、`test_dispute_close_and_image_rejection`（非 PNG/JPEG 拒绝）。
- **重新评估条件**：图片量级超过数百张/单库 500MB 时改为文件系统 + 签名 URL。
- **替代关系**：无。

### ADR-010 写操作收敛到单一入口 `act()`，并在末尾统一写审计

- **状态**：已接受（组内确认 2026-11-12）　**确认人**：项目组（组长 夏天）　**复核人**：李哲剑　**日期**：2026-11-12
- **背景**：FR-01～FR-14 都要求"每次请求校验登录凭证、角色、对象归属与当前状态"；FR-08 要求所有处置留痕。
- **比较**：A. 每个 URL 一个处理函数各自校验——易漏；B. 单入口按 `action` 分发，公共校验只在开头写一次；C. 装饰器式中间件——更优雅，但单文件下收益有限。
- **决定**：B。封禁检查、`audit` 写入固定在入口处，分支内只写业务断言。
- **理由**：把"必须做"的事放在唯一路径上，漏写不了；审计自动覆盖新动作。
- **代价**：`act()` 变长；幂等提前 `return` 的路径会跳过审计；动作名是字符串，拼错只能运行期发现（有 `未知操作` 兜底）。
- **验证**：19 项测试均经 `act()` 路径；`test_report_and_admin_audit_csv` 检查审计可见。
- **重新评估条件**：拆分模块时，改为装饰器 + 显式 `audit()` 调用，避免单函数继续膨胀。
- **替代关系**：无。

### ADR-011 通知与业务同事务写入

- **替代关系**：无。演示版接受该差异；扩展时按 TASK-08 改为事务外发送。

### ADR-012 版本升级用幂等 `migrate_db()`

- **状态**：已接受（组内确认 2026-11-12）　**确认人**：项目组（组长 夏天）　**复核人**：李哲剑　**日期**：2026-11-12
- **背景**：v1.0→v1.2 期间 `reviews` 表新增 `hidden` 等列、评分单位从 1–5 改为十分位；需要让旧 `data/campus.db` 直接可用。
- **比较**：A. 手动 SQL 升级脚本——依赖人记得执行；B. 启动时检测列缺失并 `ALTER TABLE`，老旧结构走"改名-新建-搬数据"；C. 删库重建——丢历史。
- **决定**：B，在 `executescript(schema.sql)` 之前执行。
- **理由**：使用者双击即启动，没有"先跑迁移"这一步的机会。
- **代价**：迁移逻辑与业务代码同文件；复杂迁移难以测试（只有一项 `test_legacy_database_migration`）。
- **验证**：`test_legacy_database_migration` 用旧结构库启动后校验数据与列。
- **重新评估条件**：出现不可自动判定的结构变更（如字段语义变化）时，改为带版本号的迁移表。
- **替代关系**：无。

### ADR-013 测试策略：真实 HTTP + 临时 SQLite，不用 mock

- **状态**：已接受（组内确认 2026-11-12）　**确认人**：项目组（组长 夏天）　**复核人**：李哲剑　**日期**：2026-11-12
- **背景**：需求要求并发与权限行为真实可验（AT-05、AT-08）；纯函数测试无法覆盖 `BEGIN IMMEDIATE` 与唯一索引。
- **比较**：A. 直接调用 `act()` 的函数测试——快，但绕过 HTTP 层与事务；B. `create_server(port=0)` 起真服务器 + `http.client` 真实请求 + 临时库；C. 引入 `pytest` + `requests`——增加依赖。
- **决定**：B，`unittest` 标准库，19 项用例。
- **理由**：并发用例必须真实多线程请求；临时库保证用例隔离；零新增依赖。
- **代价**：单次全量约数十秒；每个用例都要建库播种。
- **验证**：`python -m unittest discover -s tests` 全绿（执行记录见 `测试结果.txt`）。
- **重新评估条件**：用例超过 60 个或需要浏览器端到端时，引入 `playwright`。
- **替代关系**：无。

### ADR-014 演示版范围裁剪：短信、视频、两级管理员、申诉不实现
