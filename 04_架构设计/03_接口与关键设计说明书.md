## 1 通用约定

| 项 | 约定 |
| --- | --- |
| 基地址 | `http://127.0.0.1:8000`（`run.py --port` 可改） |
| 查询 | `GET /api/<资源>?参数` |
| 写操作 | `POST /api/<动作名>`，`Content-Type: application/json`，**必须是 JSON 对象** |
| 认证 | Cookie `sid`（HttpOnly、SameSite=Strict、24h）；登录后从响应或 `/api/me` 取 `csrf` |
| 认证范围 | **仅"学号+密码"**；没有手机号、短信验证码、统一身份对接（演示版裁剪，见 §7 API-D8） |
| CSRF | 写请求必须带 `X-CSRF-Token`，与服务端 `sessions.csrf` 常量时间比对；`login`/`register` 除外 |
| 来源校验 | 有 `Origin` 头时必须与 `Host` 同源 |
| 报文上限 | `Content-Length` ∈ (0, 32MB] |
| 成功响应 | `{"ok": true, ...}` 或资源对象；HTTP 200 |
| 错误响应 | `{"error": "中文原因"}`；400（业务/参数）、409（唯一约束冲突）、500（未预期异常） |
| 分页 | **无**（全量返回，演示版裁剪，见 DEV-03） |
| 空值规则 | 字符串一律 `strip()` 后判长度；未提供与空串等价 |
| 时间格式 | 交付时间入参 `%Y-%m-%dT%H:%M`（本地时区），库内为 Unix 秒 |

统一响应头（由 `Handler.send` 添加）：`X-Content-Type-Options: nosniff`、`Cache-Control: no-store`、`Content-Security-Policy: default-src 'self'; img-src 'self' data:; ...`。

| --- | --- | --- | --- | --- |
| `GET /api/me` | — | 无（未登录返回 `user:null`） | `{user, csrf}` | — |

| `GET /api/mine` | — | 登录 | `{products, favorites, notices}`（通知取最近 100 条） | 请先登录 |
| `GET /api/orders` | — | 登录 | `{orders, withdrawals}`，订单附 `review/reviewed/review_closed` | 请先登录 |
| `GET /api/messages` | `id`（商品） | 登录且为会话参与方 | `{messages}` | 请先登录 |
| `GET /api/order_history` | `id`（订单） | 登录且为订单双方 | `{confirmations}` | 不能查看他人订单 |
| `GET /api/admin` | `start`、`end`（Unix 秒） | 管理员 | `{products, users, reports, withdrawals, disputes, reviews, audit, stats}` | 需要管理员权限 |
| `GET /api/export` | `start`、`end` | 管理员 | 带 BOM 的 CSV（已完成订单） | 需要管理员权限 |

补充语义：

- `/api/products` 只返回 `status IN ('在售','已预订') AND frozen=0`；排序：`price`→价格升序、`rating`→评分降序、默认发布时间倒序。
- `/api/product` 可见条件：`frozen=0 AND status IN ('在售','已预订','已售出')`，或请求者为管理员/该商品卖家。
- `/api/review_image` 可见条件：评价未隐藏且关联订单已完成，或请求者为管理员。

## 3 写接口清单

| 动作 | 权限 | 主要校验 | 状态影响 | 通知 |
| --- | --- | --- | --- | --- |
| `register` | 匿名 | 学号 8–12 位数字；姓名 2–20；密码 ≥8 且含大小写字母与数字；学号唯一 | 新建 `users` | — |
| `login` | 匿名 | 学号+密码；同 `IP:学号` 连错 5 次锁 5 分钟 | 新建 `sessions` | — |
| `logout` | 登录 | — | 删除 `sessions` 行、清 Cookie | — |
| `publish` | 登录、未封禁 | 名称 2–50、描述 10–1000、价格 (0, 100 万]、分类 1–30、成色 1–20、图片可选 ≤5MB PNG/JPEG | 新建 `products`，`status='待审核'` | — |
| `edit` | 本人、未封禁 | 仅 `已下架/已驳回` 且未冻结 | 改内容并回到 `待审核` | — |
| `favorite` | 登录、未封禁 | 商品 `在售/已预订` 且未冻结 | **切换**：有则删、无则增 | — |
| `message` | 登录、未封禁 | 不能发给自己；必须关联该商品卖家；卖家只能回复既有咨询 | 新建 `messages` | 通知对方 |
| `order` | 登录、未封禁 | 非本人商品；商品在售未冻结；卖家未封禁；已有有效订单则幂等返回 | 新建 `orders(待接单)` + `products→已预订` | 通知卖家 |
| `accept` | 卖家 | 订单 `待接单`；交付地点 2–100；交付时间在当前之后且下单后 72h 内 | `orders→待交付` | 通知对方 |
| `cancel` | 订单双方、未封禁 | `待接单/待交付` 且双方均未确认 | `orders→已关闭` + `products→在售` | 通知对方 |
| `confirm` | 订单双方 | 订单 `待交付`（或 `已完成`，幂等） | 写本人确认时间；双方齐全 → `已完成` + `已售出` | 通知对方 |
| `withdraw` | 订单双方 | 本人确认后 2h 内；同一订单无待审申请；理由 2–500 | 新建 `withdrawals(待审核)` | 通知对方 |
| `dispute` | 订单双方 | 订单 `待交付`（已完成订单须先申请撤回） | `orders→争议处理中`，保留占用 | 通知对方 |
| `review` | 买家 | 订单 `已完成`；未评价过；未被删除；评分 1.0–5.0（步长 0.1）；正文 1–200；标签 ≤3 且白名单；图片 ≤3 张 ≤5MB | 新建 `reviews` + `review_tags` + `review_images` | 通知卖家 |
| `append_review` | 买家 | 订单 `已完成`；本人评价存在且未隐藏；追加文字 1–100 | 在原评价正文后追加 | 通知卖家 |
| `reply_review` | 卖家 | 订单 `已完成`；评价存在；正文 1–200 | 新建/更新 `review_replies` | 通知买家 |
| `delete_reply` | 卖家 | 本人订单 | 删除 `review_replies` | — |
| `hide_review` / `unhide_review` / `delete_review` | 管理员 | 理由 2–500 | `hidden=1` / `hidden=0` / 删除并写 `review_deleted` 墓碑 | 隐藏/删除不通知 |
| `report` | 登录、未封禁 | 商品存在；理由 2–500；同一人对同一商品仅一次 | 新建 `reports(待处理)` | — |
| `shelve` | 卖家 | 本人商品且在售 | `products→已下架` | — |
| `review_product` | 管理员 | 商品 `待审核`；理由 2–500；`approve` 决定通过/驳回 | `在售` 或 `已驳回` | 通知卖家 |
| `freeze` / `unfreeze` | 管理员 | 理由 2–500 | `frozen=1` / `0` | 通知卖家 |
| `ban` / `unban` | 管理员 | 理由 2–500；不能封管理员；天数 ≥7 | 写/清 `users.banned_until` | 通知本人 |
| `handle_report` | 管理员 | 举报存在；结论 2–500 | `reports→已处理` | 通知举报人 |
| `handle_withdrawal` | 管理员 | 申请 `待审核`；订单 `待交付/已完成` | 见 §4.5 | 通知申请人 |
| `resolve` | 管理员 | 订单 `争议处理中`；认定完成需至少一方确认 + 理由 ≥10 字 | 见 §4.4 | 通知双方 |
| `read_notices` | 登录 | — | 本人全部 `notices.seen=1` | — |

## 5 关键设计

### 5.1 权限矩阵（实现口径）

| 操作 | 访客 | 认证学生 | 封禁学生 | 管理员 |
| --- | --- | --- | --- | --- |
| 浏览/搜索/详情/卖家主页 | ✓ | ✓ | ✓ | ✓ |
| 发布/编辑/收藏/咨询/下单/评价/举报 | ✗ | ✓（本人且状态允许） | ✗（`act()` 开头拦截） | 不代学生操作 |
| 接单/取消/确认/撤回/争议 | ✗ | ✓（订单双方） | 确认与申诉类仍允许；新增业务拒绝 | 仅裁定，不代确认 |
| 审核/冻结/封禁/统计/导出 | ✗ | ✗ | ✗ | ✓ |

实现位置：封禁拦截在 `act()` 开头的 `new_actions` 判断（`publish/favorite/message/order/submit/edit`）；其余为分支内断言。

### 5.2 事务与锁顺序

固定顺序：**先校验 → 后写主表 → 再写从表/通知 → 末尾审计**。禁止在事务内做网络/IO 等待；图片 base64 解码目前也在事务内（已知问题，见 `01_...基线版.md` §10）。

### 5.3 幂等与冲突

| 场景 | 机制 | 返回 |
| --- | --- | --- |
| 重复下单 | 查有效订单 → 直接返回既有 `order_id` | 200 |
| 并发下单 | `one_active_order` 唯一索引 | 输家 409 |
| 重复接单/取消 | 分支内前置判断 | 200（"已经接单/关闭"） |
| 重复确认 | 仅首次写本人确认时间 | 200 |
| 重复举报 | `UNIQUE(author,product)` | 409 |
| 重复评价 | 前置查询 | 400（与"幂等"要求不一致，登记） |

### 5.4 错误与日志

- 400 的业务文案直接展示给用户，因此**文案本身是接口契约的一部分**，改动需同步前端与测试；
- 500 只回"服务器处理失败"，详情 `print` 到控制台；
- `audit` 在成功路径末尾写入；提前 `return` 的幂等路径**不写审计**（已知缺口 L-06）。

## 6 与架构决策的约束关系

| 约束 | 体现在接口上的后果 |
| --- | --- |
| ADR-003 串行写 | 所有写接口在并发下可能排队；错误用 409 表达"抢占失败" |
| ADR-007 冻结用标记 | 无"冻结"状态值；客户端必须读 `frozen` 字段判断，不能只看 `status` |
| ADR-008 整数存储 | 所有金额/评分在接口层做单位换算，前端不得直接比较数据库值 |
| ADR-010 单入口 | 未知动作名统一 400；新增功能必须同时进权限表与审计 |
| ADR-011 通知同事务 | 通知失败会连带业务失败（与 FR-14 不同，演示版已接受该差异） |

## 7 演示版裁剪与接口差异

| 编号 | 差异 | 影响 |
| --- | --- | --- |
| API-D1 | 无分页参数 | 商品量增大后响应体过大（DEV-03） |
| API-D2 | 收藏为切换语义 | 客户端重试会误删收藏，需前端防抖 |
| API-D3 | 重复评价返回 400 而非幂等成功 | 与需求 3.1 表述不一致 |
| API-D4 | 通知与业务同事务 | 与 FR-14"通知失败不撤销业务"不同，演示版接受（ADR-011） |
| API-D5 | 导出仅 CSV、仅已完成订单 | 无 Excel、无销量/举报明细（DEV-09） |
| API-D6 | 通知无类型、无单条已读 | 前端只能整批标记已读（DEV-12） |
| API-D7 | 错误码只用 400/409/500 | 无法区分"未登录/无权限/参数错"，客户端只能靠文案 |
| API-D8 | 认证只有"学号+密码" | 无手机号绑定、无短信验证码、无统一身份适配层；AT-01 的短信条款不适用（DEV-01、Q-01） |
